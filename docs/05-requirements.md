# Функциональные требования к CRM

## Область решения

MVP помогает принять заявку, назначить следующую работу и наблюдать воронку. Целевой промышленный контур дополнительно требует интеграций, прав доступа, истории событий и защиты клиентских данных.

| ID | Приоритет | Требование | Критерий приёмки | Статус |
|---|---|---|---|---|
| FR-01 | Must | Создание, чтение, изменение и удаление карточки клиента | Карточка с именем сохраняется; пустое имя отклоняется | Реализовано |
| FR-02 | Must | Поиск и фильтр по клиентам | Поиск по имени, компании, email, телефону; фильтр по статусу | Реализовано |
| FR-03 | Must | Назначение ответственного | Ответственный сохраняется и показан в списке задач | Реализовано вручную |
| FR-04 | Must | Проверка дублей по телефону/email до создания | Совпадение показывает предупреждение и ссылку на карточку | В плане |
| FR-05 | Must | Задача первого контакта с SLA 15 минут | После создания лида появляется одна открытая задача нужного типа | Реализовано |
| FR-06 | Must | Завершение задачи первого контакта | Задача закрывается; новый лид получает статус «В работе» | Реализовано |
| FR-07 | Must | Задача подготовки КП при квалификации | При первом переходе в «Квалифицирован» создаётся задача на +2 дня | Реализовано |
| FR-08 | Must | Задача повторного контакта на этапе КП/переговоров | При переходе на соответствующий этап создаётся задача на +2 дня | Реализовано |
| FR-09 | Must | Очередь открытых и просроченных задач | Список сортируется по сроку, просрочка выделяется | Реализовано |
| FR-10 | Must | Закрытие сделки с очисткой активных задач | Для «Выигран»/«Проигран» открытые задачи отменяются | Реализовано |
| FR-11 | Must | Дашборд воронки и результатов | Числа пересчитываются по текущей базе | Реализовано |
| FR-12 | Should | История событий и причина отказа | Можно восстановить даты контактов и переходов | В плане |
| FR-13 | Should | Приём из форм, почты или API с повторной отправкой | При ошибке заявка не теряется; есть журнал интеграции | В плане |
| FR-14 | Must для продакшена | Роли, вход и разграничение доступа | Менеджер видит разрешённые записи, администратор управляет правами | В плане |
| FR-15 | Should | Экспорт данных | CSV содержит все текущие карточки | Реализовано |
| FR-16 | Should | Уведомление о нарушении SLA | Руководитель получает уведомление по заданному правилу | В плане |

## Нефункциональные требования для внедрения

| ID | Требование | Проверка |
|---|---|---|
| NFR-01 | Доступ только после аутентификации и по роли | Проверки разрешённых/запрещённых сценариев |
| NFR-02 | Транспортное шифрование при сетевом доступе | HTTPS, отсутствие открытого HTTP |
| NFR-03 | Резервное копирование и восстановление | Регулярный тест восстановления базы |
| NFR-04 | Аудит изменений статуса и ответственного | Неизменяемые записи событий с автором и временем |
| NFR-05 | Согласованное время SLA и часовой пояс | Одинаковый результат в API, интерфейсе и отчётах |
| NFR-06 | Доступность и быстродействие по согласованному SLO | Нагрузочный тест после уточнения объёма данных |

Текущий локальный прототип **не удовлетворяет NFR-01–NFR-06 в полном объёме** и не должен размещаться как публичный сервис с реальными контактами. Публикация исходного кода на GitHub не означает готовности к промышленной эксплуатации.

## Критерии готовности пилота

1. Все Must-функции MVP проходят тесты и ручной сценарий.
2. Импортируемые данные очищены от дублей; права и доступ к пилотной среде согласованы.
3. Собраны базовые KPI за период до запуска.
4. Назначены владелец процесса и ответственный за просроченные задачи.
5. Согласован порядок отката и резервного копирования.
