# KPI и план измерения

Цель измерения — понять, перестали ли заявки оставаться без своевременного действия и улучшилось ли закрытие сделок. Ниже — определения для будущей реальной CRM. Синтетические записи в репозитории **не задают базовую линию**.

## Основные показатели

| KPI | Формула и единица анализа | Зачем нужен | Доступность сейчас |
|---|---|---|---|
| Соблюдение SLA первого контакта | Новые заявки с завершённой задачей первого контакта не позднее 15 минут / все заявки, для которых 15 минут уже истекли, ×100%. Зерно: заявка. | Ранний сигнал потерь P2 | В прототипе есть время задачи; для точного отчёта требуется отдельная витрина событий |
| Доля необработанных заявок за 24 часа | Заявки старше 24 часов без подтверждённого первого контакта / все заявки старше 24 часов, ×100%. | Прямой контроль «забытых» заявок | Можно вывести из задач, но импортированные исторические записи без задач исключаются |
| Win rate закрытых сделок | Выигранные / (выигранные + проигранные), ×100%. Зерно: закрытая сделка. | Проверяет конечный результат | Текущее состояние доступно на дашборде; историю периодов нужно добавить |

## Диагностические метрики

| Метрика | Определение | Реакция команды |
|---|---|---|
| Медианное время первого контакта | Медиана от поступления заявки до подтверждённого контакта | Проверить распределение и загрузку менеджеров |
| Доля задач с просрочкой | Открытые задачи со сроком в прошлом / все открытые задачи | Перераспределить очередь, проверить реалистичность SLA |
| Застой на этапе КП | Сделки на этапе «Предложение» свыше согласованного срока / все сделки на этапе | Проверить качество КП и повторных контактов |

## Ограничители качества

- **Доля дублей:** рост карточек без дедупликации может искусственно улучшать активность и ухудшать конверсию.
- **Доля фиктивных закрытий задач:** задача может быть отмечена выполненной без реального контакта. Для внедрения нужен журнал звонка/письма или выборочный аудит.

## Предварительные цели пилота

Цели ниже — ориентиры для проверки, а не обещание результата: SLA первого контакта ≥85%; необработанные заявки за 24 часа ≤5%; доля просроченных задач ≤10%. Win rate не получает числовой цели до измерения базовой линии и качества входящего потока. После 2–4 недель пилота цели пересматриваются по реальным данным.

## План измерения

1. **До запуска:** собрать 8–12 недель истории с неизменными определениями и датами по одному часовому поясу.
2. **Во время пилота:** ежедневно проверять просрочки, еженедельно смотреть SLA и необработанные заявки, ежемесячно — win rate.
3. **Сегментация:** канал, менеджер, неделя поступления, тип клиента. Не сравнивать периоды с разным составом каналов без поправки.
4. **Правило действий:** если SLA падает две недели подряд, руководитель проверяет очередь и назначение; если win rate падает при росте скорости, выборочно изучаются качество квалификации и контакта.
5. **Ограничение причинности:** улучшение после внедрения само по себе не доказывает эффект CRM. Для сильного вывода нужен сопоставимый контрольный поток или хотя бы сравнение периодов с поправкой на сезонность, маркетинг и состав лидов.
